# Chest Rush · Roadmap（顶层路线图）

> **这是什么**：全系统的顶层路径，不是 todo。记录"一定要做的关键事项"和阶段方向，
> 随演进与讨论持续补充更新。todo 管"下一次动手做什么"，roadmap 管"我们往哪去、不能丢什么"。
>
> **与 recipe 的关系**：`godot/0.recipe.md` 的开发阶段门（灰盒→手感→视觉→垂直切片→内容→发布）是**过程方法论**；
> 本文件是**内容与系统的目标路径**。两者对照使用，阶段门决定"何时配做这事"，roadmap 决定"做什么"。
>
> **当前坐标**：Phase 2 灰盒 ✅、Phase 3 手感 ✅ 已完成，正前方是 Phase 4 视觉方向 + 武器系统重构（见下）。

## 一、顶层结构决策（已定调，后续不得推翻除非重新讨论）

### 1. 章节制，而非单关主题
一个主题 = 一个**章节**：一套剧情 + 一套美术风格（如高校/商场/荒村）+ 该章节下**多个不同关卡**。
- 理由：单关一个主题对美术要求太高；章节制让一套美术资产服务多关，摊薄成本。
- 推论：**美术与地图必须是瓦片式（tile-based）可拼接**——用同一套瓦片组合出多种灵活地图。
- 现状衔接：当前 ASCII 字符串地图就是"数据驱动地图"的雏形，是瓦片机制的种子，方向一致。

### 2. 武器（鬼）系统要向"技能化"重构
当前刀/矢/域是**最小可玩原型**，不是终态。要能顺滑进化为 `0.story.md` 里的鬼技能
（草绳吊起、饿死鬼吞噬成长、换头鬼偷能力、敲门鬼读条定身等）。
- 方向：把"武器"升级为**可组合的鬼技能**：数据（伤害/冷却/范围/弹道）+ **触发逻辑钩子**（命中/击杀/读条/定身回调）。
- **先不强做抽象**——按 recipe「系统开始互相叠加时才收敛模块边界」，在加第 4、5 只鬼、出现共性时再提炼接口。
- 这是 3.next_step 里"完善攻击系统"的落点。

### 3. 玩法本质（已定，不再摇摆）
移动塔塔防：被动攻击、数值比拼、搜齐任务道具读条、穿门撤离。**不存在贪撤博弈**（已试玩证伪）。

## 三、一定要做 · 但灰盒/当前阶段暂缓（防遗忘清单）

> **规则**：想到"将来必须做"的事就记在这里，写清"为什么重要 + 什么时候做"。**宁可记多，不可漏掉。**
> 每条标注触发阶段；到了那个阶段就把它捞出来排进当时计划。

### 玩法 / 系统
- [ ] **多关卡地图机制**（P6）：关卡=数据文件（地图/开局3鬼/波次表/怪物构成/任务撤离参数），改数据不加关不改代码。**为什么**：章节制下多关是常态，必须数据驱动。
- [ ] **瓦片式可拼接地图机制**（P6）：一套瓦片组合多图，服务章节美术复用。**为什么**：章节制的技术前提。
- [ ] **关卡与装备的克制适配**（P6）：每关固定开局 3 鬼，与本关怪物特性形成克制。**为什么**：0.design 核心规则，制造"这关怎么配装"的决策。
- [ ] **跨关长期成长**（P6）：关键道具带出后可永久强化自身/扩开局装备池/解锁图鉴。**为什么**：搜打撤的长线留存钩子，0.design「通关解锁图鉴与装备」。
- [ ] **敌人机制化（看得见的规则）**（P5 起）：每只精英鬼有固定触发与手法（敲门听得见、换头看朝向、替身看得见转移线）。**为什么**：0.story 的核心乐趣——玩家靠观察学克制，不是无脑输出。
- [ ] **复苏条**（P6 或更晚）：过度强化/滞留抬高敌方强度或己方鬼失控预警。**为什么**：0.story 标志性机制，把"复苏"做成局内压力源。
- [ ] **敌方鬼也配武器/技能**（P6）：精英/Boss 有专属攻击模式。**为什么**：3.next_step 方向，丰富对抗。

### 长线留存（0.design 成瘾设计要点，P6 起）
- [ ] **保底收益机制**（P6）：战败也带走部分收益，降低挫败感。**为什么**：0.design「保底收益降低战败挫败感」。
- [ ] **梯度难度**（P6）：新手关到进阶关的难度阶梯。**为什么**：0.design「梯度难度适配新手与进阶」。
- [ ] **收集成就/全局图鉴**（P6）：通关解锁图鉴与全新开局装备，重复挑战解锁全局专属资源。**为什么**：0.design 长线留存体系。
- [ ] **战力成长可视化**（P5）：火力/血量成长的直观呈现，提升掌控感。**为什么**：0.design「战力成长可视化」。

### 美术 / 表现
- [ ] **主角全套动画**（P5）：priest 只有 idle 4 帧，缺 walk/attack/hurt/death。tiny-rpg Soldier 有全套但 100×100 Q 版风格与 dungeon 不搭，**建议定制或另选统一风格包**。**为什么**：怪物已做完整动画（idle/walk/attack/hurt/death），主角只有 idle 会显得呆板。**触发**：P5 垂直切片美术统一时。
- [ ] **Phase 4 视觉方向定调**（P4，当前）：AI 生图探索"恐怖喜剧+诡异复苏"，统一镜头/色板/轮廓/信息优先级。**为什么**：先建视觉承诺再堆资产，避免返工。
- [ ] **瓦片美术资产**（P6）：按章节主题产出可拼接瓦片集。**为什么**：章节制的资产形态。
- [ ] **音频**（P5）：低压力循环 BGM + 摧毁/击杀/搜集/升级全链路音效。**为什么**：0.design 成瘾设计要点。

### 工程 / 工具
- [ ] **Web 版重部署**（持续）：玩法稳定后重新导出 gh-pages，让朋友玩到新版。**为什么**：试玩反馈是生命线。**触发**：本轮改动累积到值得收反馈时。
- [ ] **存档/持久化**（P6）：跨关成长、图鉴、解锁需要落盘。**为什么**：多关长线的前提。
- [ ] **性能与对象池**（P6 或出现卡顿征兆时）：后期怪多/弹多时飘字与弹体对象池。**为什么**：现在量小不做，超预期再做。

### 明确暂不做（防范围蔓延，recipe 原则四）
- 背包大系统、复杂装备树、完整剧情演出、联网、大量敌人变体——**核心循环未经外部测试前不做**。

## 四、怎么维护这份 roadmap

1. **它是活的**：每次讨论出新方向/新必做项，就更新本文件；todo 只管下一次动手。
2. **"必做但暂缓"一律进第三节**，不许只在脑子里——这是它存在的首要理由。
3. **阶段推进时回读**：进入新阶段（如 P5）先翻 roadmap，把该阶段的暂缓项捞出来排期。
4. **删东西也要记**：砍掉某个方向时，在对应条目注明"已砍+原因+日期"，保留决策痕迹（recipe 原则五）。
