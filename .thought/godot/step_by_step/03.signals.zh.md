# 使用信号（Using signals）

> 原文：`godot-docs/getting_started/step_by_step/signals.rst`

本篇介绍 **信号（Signal）**：节点在发生特定事件时发出的消息（例如按钮被按下）。其他节点可以**连接**到这个信号，事件发生时调用对应函数。

---

## 信号是什么？为什么重要？

信号是 Godot 内置的**委托机制**：一个游戏对象可以对另一个对象的变化做出反应，而**不必互相持有引用**。这降低了**耦合**，代码更灵活。

例子：屏幕上有代表玩家生命值的生命条。玩家受伤或喝药时，生命条要更新——在 Godot 里用**信号**最合适。

自 Godot 4.0 起，信号和 Callable 一样是**一等类型**，可以当参数传递，编辑器自动补全更好，也比字符串连接更不容易出错。

> 信号本质上是**观察者模式**。first_2d_game 里会大量用到：敌人死了通知计分、玩家死了通知 Game Over，等等。

本篇会用信号实现：按按钮让上一篇的 Godot 图标**开始/停止**运动。

> **命名规范（本项目跟官方一致）**
> - **GDScript**：类名 PascalCase，变量/函数 snake_case，常量 ALL_CAPS
> - 信号回调函数惯例：`_on_节点名_信号名`，例如 `_on_button_pressed`

## 在编辑器里连接信号

目标：把 Button 的 **`pressed`** 信号连到 Sprite2D，按下时切换运动开/关。

Sprite2D 上需已挂载脚本（上一篇已完成）。

1. 选中 **Button** 节点
2. 右侧切到 **Signals（信号）** 标签（在 Inspector 旁边）
3. 双击 **`pressed`** 信号
4. 在连接窗口里，接收节点选 **Sprite2D**
5. 接收方法名用默认生成的 **`_on_button_pressed`**
6. 点 **Connect**，会自动跳转到 Script 工作区

配图：`img/signals_10_node_dock.webp` … `signals_14_signals_connection_info.webp`

> **简单模式 vs 高级模式**：简单模式只能连到有脚本的节点并自动生成回调；高级模式可连任意节点/内置函数。窗口右下角 **Advanced** 切换。
>
> 若用 VS Code 等外部编辑器，可能不会自动生成代码，需用下文「代码连接」方式。

编辑器会生成带 `pass` 的空函数。把 `pass` 换成：

```gdscript
func _on_button_pressed():
    set_process(not is_processing())
```

### 含义

- Sprite2D 靠 `_process()` 运动
- `set_process(true/false)` — 开启/关闭每帧处理
- `is_processing()` — 当前是否在跑 `_process`
- `not` — 取反，实现**开关切换**

运行前，确认 `_process` 是**自动旋转移动**版本（与 02 篇一致）：

```gdscript
func _process(delta):
    rotation += angular_speed * delta
    var velocity = Vector2.UP.rotated(rotation) * speed
    position += velocity * delta
```

按 **F6** 运行，点按钮，图标应开始/停止运动。

## 用代码连接信号

编辑器连接适合固定场景；**在脚本里动态创建节点**时，必须在代码里连接。

### 添加 Timer 节点

1. 回到 2D 工作区（顶部点 **2D** 或 **Ctrl + F1**）
2. 右键 **Sprite2D** → **Add Child Node** → 搜索 **Timer** 并添加
3. 选中 Timer，Inspector 里勾选 **Autostart**

### 在 `_ready()` 里连接

节点**完全实例化**后，引擎会自动调用 `_ready()`——适合在这里做初始化连接。

```gdscript
func _ready():
    var timer = get_node("Timer")
    timer.timeout.connect(_on_timer_timeout)
```

| 代码 | 含义 |
|------|------|
| `get_node("Timer")` | 按**子节点名称**获取 Timer 引用 |
| `timer.timeout.connect(...)` | 当 Timer 发出 `timeout` 信号时，调用指定函数 |

若把 Timer 改名为 `BlinkingTimer`，就要写 `get_node("BlinkingTimer")`。

添加回调函数，用 Timer 切换可见性（闪烁）：

```gdscript
func _on_timer_timeout():
    visible = not visible
```

`visible` 是 bool，控制节点是否显示。`not visible` 即在 true/false 间切换。

运行 `node_2d.tscn`：图标应约每秒闪烁一次，同时仍可按钮控制运动。

## 自定义信号（参考）

以下不依赖前面练习项目，供以后写游戏逻辑时查阅。

在脚本里声明信号，例如玩家生命归零时通知 UI：

```gdscript
extends Node2D

signal health_depleted

var health = 10
```

> 信号名通常用**过去式动词**，表示「已经发生的事」。

自定义信号和内置信号一样，会出现在 Signals 面板，可同样连接。

**发出信号**：

```gdscript
func take_damage(amount):
    health -= amount
    if health <= 0:
        health_depleted.emit()
```

**带参数的信号**：

```gdscript
signal health_changed(old_value, new_value)

func take_damage(amount):
    var old_health = health
    health -= amount
    health_changed.emit(old_health, health)
```

## 完整脚本参考

```gdscript
extends Sprite2D

var speed = 400
var angular_speed = PI


func _ready():
    var timer = get_node("Timer")
    timer.timeout.connect(_on_timer_timeout)


func _process(delta):
    rotation += angular_speed * delta
    var velocity = Vector2.UP.rotated(rotation) * speed
    position += velocity * delta


func _on_button_pressed():
    set_process(not is_processing())


func _on_timer_timeout():
    visible = not visible
```

## 小结

- 节点在特定事件发生时**发出信号**
- 其他节点**连接**信号并执行回调
- 用途极广：进入区域、碰撞、UI 变化、拾取金币（`Area2D` 的 `body_entered`）等

**first_2d_game** 里：敌人碰到玩家 → 发信号 → 主场景 Game Over；HUD 按钮 → `pressed` → 开始游戏。和本篇是同一套机制。

## 本篇你要记住的概念

| 概念 | 一句话 |
|------|--------|
| 信号 | 事件通知，发送方不必知道谁在听 |
| 编辑器连接 | Signals 面板 → 双击信号 → Connect |
| 代码连接 | `信号.connect(回调函数)`，常在 `_ready()` 里 |
| `_ready()` | 节点进场景树且就绪后调用一次 |
| `get_node("名字")` | 按路径名取子节点（默认直接子节点） |
| 自定义信号 | `signal 名字` + `名字.emit()` |
